# 적조 위험도 지수 — 01. 요구사항 정리

작성 2026-10-02 · 상태 **설계 기반 문서 (결정 아님)** · 계기: 대시보드 측 지적 — "API 모듈 설계에 통합계획서 v1.5 7.4절 설계 B(적조 위험도 지수)가 없다"

이 문서는 v1.5가 위험도 지수에 대해 요구하는 것을 **원문 그대로 모으고, 이 모듈의 용어로 옮긴다.** 설계 선택지와 결정할 것은 `03_설계_쟁점과_결정_목록.md`에 있다.

---

## 1. 현재 상태 — 왜 빠져 있었나

| 문서 | 기술 |
| --- | --- |
| 제작계획서 0.2.1절 | "적조 위험도 지수(v1.5 7.4절) — **이 모듈의 범위인지 정해진 적이 없다.** v1.5 1.3.2절 대시보드 배치에는 없다" → **팀 결정 전까지 설계·구현하지 않는다** |
| 제작계획서 11절 | "적조 위험도 지수(v1.5 7.4절)의 범위 — 미정, 설계·구현하지 않음(0.2.1절) — 팀" |
| v1.5 1.3.2절 (화면 구성, v1.5 확정) | 계기판 8종(수온·물때·풍속·기온·염분·적조·DO·클로로필a)에 **위험도 지수가 없다** |
| v1.5 7.4절 | 설계 B로 **설계가 있다**(아래 2절) |
| v1.5 일정표(4주차 10/09~10/15) | "`interpolation-svc`·`prediction-svc`, **위험도 지수(7.4)**, Argo CD …" — 일정에는 들어 있다 |

**정리**: v1.5 안에서 7.4절(설계 있음·일정 있음)과 1.3.2절(화면 배치 없음)이 어긋나 있었고, 제작계획서는 그 어긋남 때문에 범위를 미정으로 두었다. 대시보드 측이 이번에 화면에 필요하다고 밝혔으므로 **0.2.1절의 "범위 미정"을 해소할 근거가 생겼다** — 범위 편입은 팀 결정과 계획서 개정으로 한다(제작계획서 A.8).

## 2. v1.5 7.4절 원문 요구

| 요구 | 원문 | 종류 |
| --- | --- | --- |
| R-1 | "**모델이 아니라 투명한 가중 합산이다.** 블랙박스를 만들지 않는 것이 요점이다" | 원칙 |
| R-2 | 출처 등급 **`INTERPOLATED`** | 등급 |
| R-3 | 알림 **금지** — 화면 참고용 | 발송 |
| R-4 | 가중치 **Git 관리** → GitOps 시연 소재 | 설정 |
| R-5 | 근거 노출 — **항목별 기여도를 화면에 분해 표시** | 출력 |
| R-6 | 항목 4개와 가중치(아래 표) | 계산 |
| R-7 | `freshness` 필드 — "실시간으로 움직이는 건 적조속보와 수온뿐이고 나머지는 기준선이다. 화면에도 그대로 나타난다" | 출력 |
| R-8 | `quality_gate: min_factors_ok: 2`, `on_insufficient: NONE` — "NEAREST로 떨어지지 않는다" | 품질 |
| R-9 | 화면 예시: 항목별 값·판정·기여도·신선도, 고지문 3줄("참고 지표", "알림을 보내지 않음", "공식 판단은 수과원 속보") | 표시 (대시보드) |
| R-10 | "**클로로필 — 관측값 이상 제외**" — 설계 A(품질 판정)와 B가 맞물린 결과를 화면에 보인다 | 품질 ↔ 출력 |

## 3. 7.4절이 기대는 다른 절

| v1.5 절 | 위험도 지수에 걸리는 내용 |
| --- | --- |
| 1.4 절대 원칙 | 추정을 실측처럼 보이게 하지 않는다 — 지수는 계산값 |
| 4.3 실시간 축 | 실시간성은 적조속보와 수온(`dtRecent`)뿐. 나머지는 맥락(기준선) — R-7의 근거 |
| 4.6 출처 등급 | `INTERPOLATED` = "복수 정점 IDW — 정점 수·거리·기대오차 — 알림 **금지**". `BASELINE` = 저빈도 조사 기준선 — 알림 금지 |
| 4.6.1 표시 축 / 발송 축 | 계산값은 표시 라벨이 무엇이든 **발송 불가**. 밴드는 "**7.4절 위험도 지수 입력용**"으로 정의됐고, 그것을 보간 오차 평가에 전용한 것이 설계 오류였다(오분류율 여름 39.27% / 가을 7.51%) |
| 4.6.2 화면 표기 | 배지 4종(`추정`·`인근 실측`·`공식 발표`·`센서 없음`) — 지수의 배지는 7.4절 예시상 "(참고)" |
| 7.3 설계 A | R1(염분 < 31 생물부착)·R2(클로로필 급등 해조류 간섭) — 지수 입력에서 "관측값 이상 제외"의 출처 |
| 7.5 정확도를 평가하지 않는다 | 측정하는 것은 둘 — ① 품질 게이트가 이상 정점을 실제로 배제했는가 ② 장애 시 `NEAREST`로 조용히 떨어지지 않고 `NONE`으로 갔는가 |
| 14.2 / 부록 "계절 편차 5.2배" | 여름 수온이 22~28℃에 거의 균등 분포 — **밴드 경계 ±0.5℃ 인접 표본 여름 43.1%·가을 32.1%** |

## 4. 이 모듈의 용어로 옮기기

| v1.5 표현 | 이 모듈 (제작계획서 4.8·5.5절, CLAUDE.md 6절) |
| --- | --- |
| 출처 등급 `INTERPOLATED` | 두 열로 나뉜다 — `derivation = COMPUTED`(값의 유래), `provenance`(영역 판정). v1.5의 "등급"을 `provenance` 하나에 그대로 넣을지는 쟁점(03 문서 D-5) |
| 알림 금지 | `alertable = false` — 불변식 "`COMPUTED`면 `alertable`은 언제나 `false`"(N11)가 이미 보장한다 |
| 가중치 Git 관리 | 설정 세 종류 중 **판정 정의**(`config/definitions.yaml`, 이미지 포함, CI 게이트) 후보 — 값이 바뀌면 지수의 뜻이 바뀐다. 운영 조정(ConfigMap)과 구분 필요(03 문서 D-4) |
| 항목별 기여도 분해 표시 | 표시는 대시보드(배지·문구·고지문). 이 모듈은 **분해에 필요한 값**(항목별 입력값·판정·기여도·신선도·근거 키)을 결과 테이블로 넘긴다 — 대시보드 계약(5.5절) 확장 |
| `on_insufficient: NONE` | `provenance = NONE` + `none_reason`. 단 "`NONE`이어도 계산할 수 있었던 값은 저장한다"(CLAUDE.md 7절) — 항목 부족으로 합산이 무의미한 경우와 구분 필요 |
| "NEAREST로 떨어지지 않는다" | 금지 규칙 "추정이 멈췄을 때 최근접 관측값으로 대체하지 않는다 — `NONE`으로 둔다"와 같은 결 |
| 클로로필 관측값 이상 제외 | 품질 규칙 R2 결과(`SENSOR_QUALITY` 플래그)가 항목에서 빠지는 것 — 이 모듈은 이미 `flags`에 남긴다 |
| 화면 고지문·"(참고)" | **대시보드 소관** — 결과 테이블에 넣지 않는다(금지 규칙: 배지·화면 문구를 결과 테이블에 넣거나 정하지 않는다) |

## 5. 대시보드 측 요청 — 확인된 것과 안 된 것

| 항목 | 상태 |
| --- | --- |
| 위험도 지수가 화면에 필요하다 | **확인** — 양식장 상세에 "적조 위험도 (참고)" 카드 자리가 이미 있다(현재 "지수 범위 미정 — 계산하지 않음" 표시) |
| 화면 위치·형태 | **확인** — 적조 계기판 안의 보조 표시. 항목 카드 4개·메인·목록에는 넣지 않음(공식 등급과 섞이지 않게). 축 `red_tide_risk` 한 행 허용 — 위험도 카드에만 씀 (Q1) |
| 필요한 필드 | **확인** — 항목별 분해 필요(`risk_index_factors` 신설 요청), 항목별 `source_ref`·`observed_at_utc` 요청, `lower`·`upper` 산출 요청(숫자로는 안 보이고 단계 경계 걸침 표시에 씀), 제외 사유 코드 목록 요청 (Q2·Q3·Q4·Q8) |
| 갱신 주기 기대 | **확인** — 입력이 새로 오면 재계산(약 10분)으로 충분. `computed_at_utc`·항목별 `observed_at_utc`만 있으면 됨 (Q5) |
| 이력 필요 여부 | **확인** — 1차 불필요. 넣는다면 합산값만(`farm_reading_history`), 분해 이력 불필요 (Q6) |
| `NONE` 화면 처리 | **확인** — W2 그대로, `axis_status` `NOT_USABLE` + `reason`으로 문구 (Q7) |
| 일정 | **확인** — 4주차(10/09~10/15). 계약(`tables-v3`) 초안·예시 행을 받으면 연결 1~2일 (Q9) |
| 대시보드 추가 확인 4건 | 단계 코드 주체 · 항목 단위·판정 값 목록 · 기여도 의미 · 염분 입력 — 회신 초안은 `05_대시보드_추가확인_회신.md` |

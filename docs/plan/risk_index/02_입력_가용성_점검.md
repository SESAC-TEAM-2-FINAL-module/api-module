# 적조 위험도 지수 — 02. 입력 가용성 점검

작성 2026-10-02 · 상태 **설계 기반 문서 (결정 아님)** · 기준: 제작계획서 개정 18 작업 트리, v1.5 7.4절

v1.5 7.4절의 항목 4개가 **이 모듈이 이미 만드는 데이터로 채워지는가**를 항목별로 본다. 새 공공 API는 필요 없다 — 네 항목 모두 채택 API 4종 안에 있다.

---

## 1. 요약

| 항목 | 가중치 | 이 모듈의 원천 | 그대로 쓸 수 있나 | 걸리는 점 |
| --- | --- | --- | --- | --- |
| `nearby_bulletin` | 0.40 | `farm_readings`(axis `red_tide`) ← `bulletins`·`bulletin_details`·`bulletin_detail_areas`·`areas` | **대체로 가능** | "인접 권역"의 범위, "밀도 등급 반영"의 점수표가 정의되지 않음 |
| `water_temp_band` | 0.30 | `farm_readings`(axis `water_temp`) — IDW, `lower`·`upper` = ∓P95 | **가능, 단 판별력 문제** | P95 2.48℃가 밴드 폭(2·3℃)과 같은 크기 — 밴드 판정이 자주 뒤집힌다 |

## 2. 항목별

### 2.1 `nearby_bulletin` (0.40, realtime)

| 점검 | 내용 |
| --- | --- |
| 원천 | `grading`이 이미 양식장마다 적조 현재값을 고른다(제작계획서 4.8절) — 양식장 좌표가 **반경 안에 드는 해역**(`areas`, 여럿 가능)의 세부 행 중 유효 기간(`bulletin.current_window_days: 3`) 안 최신 속보의 최고 등급 행. 결과 `farm_readings`의 `value`(max_density)·`grade` |
| 신선도 | 정기 수집 1시간(시즌 밖 6시간), 30일 창(개정 18). 적조 신선도 임계 `red_tide_bulletin: 72`h(운영 조정) |
| 품질 | 직전 원문 대조(개정 18)는 운영 신호라 값에 영향 없음 |
| **쟁점 ①** | v1.5는 "**인접** 권역"이다. 이 모듈의 대응은 "반경 안 해역"이다 — 인접(이웃 해역까지)을 넓힐지, 지금 대응을 그대로 쓸지 정해야 한다. 이웃 해역 관계는 시드(`areas`)에 없다 |
| **쟁점 ②** | "1.0 (밀도 등급 반영)" — 등급별 점수(예: `WARNING` 1.0 / `ADVISORY` … / `PRE_ADVISORY` … / `UNKNOWN` … / `NOT_GRADED`·`NONE` 0)가 없다. `UNKNOWN`(밀도 없음)·`NOT_GRADED`(비대상 종)의 점수도 정해야 한다 |
| 쟁점 ③ | 유효 기간 안 속보 없음 = 0점(정상적 침묵)인지, "항목 OK"로 셀지(품질 게이트 R-8) |

### 2.2 `water_temp_band` (0.30, realtime)

| 점검 | 내용 |
| --- | --- |
| 원천 | `farm_readings` axis `water_temp` — IDW 추정 `value`, `lower`·`upper` = `value` ∓ 오늘의 오차 P95, `provenance`(현 P95 2.48 → `INTERPOLATED` 수준), `derivation = COMPUTED` |
| 신선도 | `interp.done`마다(조위 적재 10분 주기). 신선도 임계 `water_temp: 3`h, 추정 지연은 `INTERPOLATION_STALE` |
| **쟁점 ④ (판별력)** | 밴드 폭: 22~24℃ = 2℃, 24~27℃ = 3℃. 오차 P95 2.48℃는 밴드 폭과 같은 크기다. v1.5 자신이 "밴드 판정이 뒤집히지 않으려면 오차가 밴드 폭의 절반 미만이어야 한다"(4.6.1절)고 적었고, 여름 오분류율 39.27%를 실측했다. **밴드는 "지수 입력 전용"으로 정의됐으므로 쓰는 것은 v1.5와 맞지만, 점수가 오차 안에서 흔들린다는 것을 출력에 드러낼지** 정해야 한다 — 선택지는 03 문서 D-7 |
| 쟁점 ⑤ | 수온 `provenance = NONE`(P95 > 3.0, 제외 구역 등)일 때 이 항목을 "OK 아님"으로 셀지 |

### 2.3 `salinity_band` (0.15, survey)

| 점검 | 내용 |
| --- | --- |
| 원천 (가) | `farm_readings` axis `salinity` — `dtRecent` 최근접 활성 관측소 실측(`MEASURED`, `provenance` `NEAREST`, 하구 관측소 `DT_0016`이면 `NONE`). **실시간**(10분) |
| 원천 (나) | `line_observations` 표층(`line.surface_rule: INCLUDE`) — 정선 정점. **결과 테이블 축이 아니다**(DO 축만 정선에서 채운다). 품질 R1(< 31 psu 생물부착 → `SENSOR_QUALITY`) 적용 대상 |
| **쟁점 ⑥ (원천 충돌)** | v1.5 7.4절은 `freshness: survey # ② 정선관측 기준선`이다. 그런데 v1.5 4.3절(v1.3 재확정)은 `dtRecent` 염분을 **준실시간 축으로 승격**했고, 1.3.2절 염분 계기판도 "인근 해역 실측 10분"이다. 7.4절 주석이 v1.3 승격 이전 기술일 가능성이 있다 — **어느 원천을 쓸지와 `freshness` 표기**를 정해야 한다 |
| 쟁점 ⑦ | 규칙이 "32 ≤ s ≤ 33 → 0.5"뿐이다 — 범위 밖은 0인지, 최대 기여가 0.15 × 0.5 = 0.075인 것이 의도인지(화면 예시 "+0.08"과 맞으므로 의도로 보인다) |

### 2.4 `chlorophyll_level` (0.15, survey)

| 점검 | 내용 |
| --- | --- |
| 원천 | `farm_readings` axis `chlorophyll` — 거리 한계 10km 안 어장환경 정점의 표층(`CHL_S`) 최신 조사값(`SURVEY`, `BASELINE`). 이전 조사값은 `survey_observations`(PK 정점·`observed_at_utc`·층·항목 — 개정 14)에 이력으로 있다 |
| 신선도 | 연 4회 조사, 연 단위 게시 추정. 신선도 임계 `chlorophyll: null`(판정 정의 — 게시 감시로 판정, `PUBLICATION_PENDING`). v1.5 기준 최신 게시 2025-11 조사분 |
| 품질 | R2(> 10 ㎍/L 이고 급등 > 5 → `SENSOR_QUALITY`) — `flags`에 남는다. v1.5 R-10 "관측값 이상 제외"가 이것 |
| **쟁점 ⑧** | "최근 조사 대비 상승이면 가중" — 비교 대상(직전 조사 / 같은 달 전년 / 최근 N회 평균), 상승 기준(절대·비율), 점수(0/1 또는 단계)가 없다 |
| 쟁점 ⑨ | 조사값이 수개월 묵었을 때 항목을 "OK"로 셀지 — v1.5는 "조사 연월을 반드시 함께 표시"만 요구한다 |
| 참고 | `chlorophyll` 조사 기준 추정(`COMPUTED`) 스위치는 기본 꺼짐(제작계획서 4.8절). 위험도 지수는 조사값을 쓰면 되고 이 스위치와 무관하다 |

## 3. 품질 게이트 (R-8) 입력

`min_factors_ok: 2` — "OK 항목"이 2개 미만이면 `NONE`. "OK"의 정의가 v1.5에 없다. 이 모듈에서 쓸 수 있는 판단 재료:

| 재료 | 위치 | 뜻 |
| --- | --- | --- |
| 값 존재 | `farm_readings.value` | 계산·조회가 됐는가 |
| 영역 판정 | `farm_readings.provenance` ≠ `NONE` | 신뢰 기준 안인가 |
| 품질 플래그 | 원천 행 `flags`(`SENSOR_QUALITY`·`STALE_SUSPECT`) | 값이 이상 판정을 받았나 |
| 침묵 분류 | `axis_status.state` | 지금 정상인가(신선도·장애 포함) — 단 `evaluation`이 쓰는 표라, 지수를 계산하는 단계가 읽으면 단계 순서가 생긴다(03 문서 D-2) |

→ 정의 선택지는 03 문서 D-6

## 4. 새로 필요한 것

| 필요 | 이유 |

| 결과 저장 위치 | 합산값만이면 `farm_readings`에 축 하나(예: `red_tide_risk`)로 들어갈 수 있다. **항목별 분해(R-5)**는 `farm_readings` 한 행에 담기지 않는다 — 항목 행을 담을 표가 필요하다(03 문서 D-3) |

| 시드 | 이웃 해역을 쓰기로 하면 `areas` 간 인접 관계 |

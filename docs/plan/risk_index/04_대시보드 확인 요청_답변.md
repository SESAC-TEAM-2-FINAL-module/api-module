# 적조 위험도 지수 — 04. 대시보드 측 답변

작성 2026-10-02 · 보내는 쪽: 대시보드(웹 서비스) · 받는 쪽: API 모듈
원문: `04_대시보드 확인 요청.md`

**전제에 동의합니다.** 모듈은 값과 판정, 대시보드는 표시만. 지수는 계산값이라 `alertable = false`, 지수로 알림을 보내지 않습니다 (웹은 지금 알림을 앱 안 알림함으로만 보내는데, 위험도 지수는 알림 대상에서 이미 빠져 있습니다).

**현재 대시보드 상태 (참고):** 양식장 상세 화면에 "적조 위험도 (참고)" 카드 자리가 이미 있습니다 — 게이지(단계) · 항목별 기여도·신선도 목록 · 고지문("참고 지표, 알림 없음, 공식 판단은 수과원 적조속보"). 결과 테이블이 없어 지금은 "지수 범위 미정 — 계산하지 않음"으로 표시합니다. 화면 모양은 가짜 데이터 기준으로 먼저 만든 것이라, **모듈 쪽 결과 테이블이 정해지면 그쪽에 맞춰 바꾸겠습니다.**

## 답변

| # | 질문 | 답 |
| --- | --- | --- |
| Q1 | 화면 위치 | **"적조 계기판 안의 보조 표시"에 가깝습니다.** 4개 항목 카드(적조·수온·염분·클로로필a)에는 넣지 않고, 양식장 상세의 별도 "적조 위험도 (참고)" 카드에 둡니다. 메인 대시보드·양식장 목록에는 넣지 않습니다 — 공식 적조 등급과 섞여 보이지 않게 하려는 것입니다. 축으로 두셔도 됩니다(`farm_readings`·`axis_status` 한 행, 축 `red_tide_risk`). 웹은 이 축을 항목 카드가 아니라 위험도 카드에만 씁니다 |
| Q2 | 항목별 분해 | **필요합니다.** 화면이 이미 항목별 값·판정·기여도·신선도를 보여 주는 구조입니다. `risk_index_factors`(가칭) 신설을 부탁드립니다 |
| Q3 | 항목별 근거 보기 | **1차에는 화면 동선이 없어도 됩니다.** 다만 항목별 `source_ref`·`observed_at_utc` 는 넣어 주시면 좋겠습니다 — 신선도 표시("8분 전")에 `observed_at_utc` 를 쓰고, 근거 보기는 나중에 `source_ref` 로 붙이겠습니다 |
| Q4 | 범위(`lower`~`upper`) | **산출해 주시면 좋겠습니다.** 화면에 숫자 범위를 그대로 보이지는 않을 생각입니다(사용자 혼란). 대신 범위가 단계 경계에 걸치면 "단계 경계 — 오차 안에서 달라질 수 있음" 정도로 표시하는 데 쓰겠습니다. 단계 자체는 아래 "추가 확인 1"을 봐 주세요 |
| Q5 | 갱신 주기 | **입력이 새로 오면 다시 계산하는 방향(약 10분)으로 좋습니다.** 대시보드는 30초마다 읽으므로 주기와 무관합니다. `computed_at_utc` 와 항목별 `observed_at_utc` 만 있으면 됩니다 |
| Q6 | 이력 | **1차에는 필요 없습니다.** 나중에 넣는다면 합산값만으로 충분하고(`farm_reading_history`), 분해 이력 표는 필요 없습니다 |
| Q7 | 신뢰할 수 없을 때(`NONE`) | **W2 그대로 적용해 주세요.** 웹은 값·게이지를 숨기고 사유만 보입니다. `axis_status` 가 `NOT_USABLE` + `reason` 이면 그 사유로 화면 문구를 붙이겠습니다 |
| Q8 | 제외 사유 | **보일 생각입니다** (예: "클로로필 — 관측값 이상 제외"). 사유 코드 목록을 넘겨주시면 웹이 문구를 붙입니다 |
| Q9 | 일정 | **4주차(10/09~10/15) 그대로 좋습니다.** 화면 자리는 이미 있어서, 결과 테이블 계약(`tables-v3`)과 예시 행을 받으면 대시보드 연결은 1~2일이면 됩니다. 계약 초안이 먼저 나오면 가짜 데이터로 미리 맞춰 두겠습니다 |

## 대시보드 쪽 추가 확인

1. **단계(레벨)는 누가 정하나요?** 지금 화면 게이지는 단계(예: 매우 낮음 ~ 매우 높음)로 그립니다. 웹은 판정을 다시 하지 않는 원칙이라, `value`(0~1)에서 단계를 웹이 직접 자르면 판정이 됩니다. **단계 코드(또는 단계 경계값)를 모듈이 넣어 주실 수 있을까요?** 계획서 7.4절에 구간이 정해져 있다면 그 기준이면 됩니다.
2. **항목 이름·단위 목록:** `factor` 코드(`nearby_bulletin` · `water_temp_band` · `salinity_band` · `chlorophyll_level`)별 입력값 단위와 판정 값 목록을 주시면 화면 문구를 맞추겠습니다.
3. **가중치·기여도의 의미:** 기여도가 "가중치 × 항목 점수"인지, 합이 `value` 와 같아지는지 알려 주시면 화면에서 합계 검산 표시를 할지 정하겠습니다.
4. **염분 입력:** 지수의 `salinity_band` 는 어떤 염분을 쓰나요? 웹은 지금 염분 화면을 가까운 조위관측소 실측으로 보이는데(모듈 계산 염분 대신 — 임시), 지수 입력이 계산 염분이면 화면 값과 지수 근거 값이 달라 보일 수 있습니다. 같은 기준이면 좋겠습니다.

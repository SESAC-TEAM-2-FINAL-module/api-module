# 적조 위험도 지수 — 04. 대시보드 측 확인 요청

작성 2026-10-02 · 보내는 쪽: API 모듈 · 받는 쪽: 대시보드(웹 서비스) 팀 · 상태 **질문지 (결정 아님)** — 범위 편입(D-1)은 팀 결정 전이다 · **답변 도착 2026-10-02** → `04_대시보드 확인 요청_답변.md`

통합계획서 v1.5 7.4절(설계 B — 적조 위험도 지수)이 API 모듈 설계에 빠져 있다는 지적을 받았습니다. 범위 편입이 정해지면 모듈 쪽에서 계산하는 안(03 문서 D-1 A, 제안)을 전제로 설계 자료를 준비하고 있습니다. 결과 테이블 모양을 정하기 전에 아래를 확인하고 싶습니다. 답을 주시면 결과 테이블 계약(`tables-v3`, 예정)에 반영합니다.

**전제** — 지금 계약과 같은 원칙입니다.
- 모듈은 **값과 판정**(합산값, 항목별 입력·점수·기여도, 근거 키, 상태)을 결과 테이블에 넣습니다
- **표시**(배지 "(참고)", 고지문, 색, 위치, 문구)는 대시보드가 정합니다 — 모듈은 문구를 넣지 않습니다
- 지수는 계산값이라 `alertable`은 언제나 `false`입니다. 지수로 사용자 알림을 보내지 않습니다(v1.5 7.4절)

## 질문

| # | 질문 | 모듈 쪽 설계에 미치는 영향 |
| --- | --- | --- |
| Q1 | 화면 어디에 두나요? (1.3.2절 계기판을 하나 더 / 적조 계기판 안의 보조 표시 / "근거 보기" 층만) | 축으로 둘지(`farm_readings`·`axis_status` 한 행) |
| Q2 | 합산값만 필요한가요, **항목별 분해**(v1.5 7.4절 화면 예시 — 항목별 값·판정·기여도·신선도)까지 필요한가요? | 분해 표(`risk_index_factors`, 가칭) 신설 여부 |
| Q3 | 항목별로 원천 행을 따라가는 "근거 보기"가 필요한가요? (예: 인접 속보 → 그 속보, 수온 → 그 IDW 실행) | 분해 표에 항목별 `source_ref` |
| Q4 | 지수도 수온처럼 **범위**(`lower`~`upper`)로 보일 생각이 있나요? 수온 추정 오차(P95 약 2.5℃)가 밴드 폭(2~3℃)과 같은 크기라, 같은 수온이라도 항목 점수가 오차 안에서 달라질 수 있습니다 | 지수 `lower`·`upper` 산출 여부 |
| Q5 | 갱신 주기 기대 — 수온이 바뀔 때마다(약 10분) / 속보가 바뀔 때만 | 계산 계기(모듈은 입력이 새로 오면 다시 계산하는 방향) |
| Q6 | 이력(시계열 그래프)이 필요한가요? 합산값만 / 항목 분해까지 | `farm_reading_history`로 충분한지, 분해 이력 표가 필요한지 |
| Q7 | 항목이 부족해 지수를 신뢰할 수 없을 때(`provenance = NONE`) 화면 처리 — 계약 W2("NONE 값은 표시하지 않는다")를 그대로 적용해도 되나요? | 현재 계약 그대로 둘지 |
| Q8 | 항목에서 이상값을 뺐을 때(v1.5 예시 "클로로필 — 관측값 이상 제외") 화면에 사유를 보일 생각인가요? 사유 코드 목록이 필요하면 모듈이 정해 넘깁니다 | 분해 표의 제외 사유 열과 코드 목록 |
| Q9 | 원하는 일정 — v1.5 일정표는 4주차(10/09~10/15)에 위험도 지수를 두고 있습니다 | 계획서 개정·지시서 순서 |

## 참고 — 모듈이 넘길 예정인 값 (가칭, 확정 아님)

| 위치 | 필드 |
| --- | --- |
| `farm_readings` (축 `red_tide_risk`) | `value`(0~1), `lower`·`upper`(Q4에 따라), `derivation = COMPUTED`, `provenance`(`INTERPOLATED` / `NONE`), `none_reason`, `alertable = false`, `computed_at_utc` |
| `risk_index_factors` (Q2에 따라) | `farm_id`, `factor`(`nearby_bulletin`·`water_temp_band`·`salinity_band`·`chlorophyll_level`), 입력값, 항목 점수, 가중치, 기여도, OK 여부, 제외 사유, 입력의 `source_ref`·`observed_at_utc` |
| `axis_status` (축 `red_tide_risk`) | `state`·`reason` — 항목 부족이면 `NOT_USABLE` |

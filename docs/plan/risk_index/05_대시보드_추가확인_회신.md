# 적조 위험도 지수 — 대시보드 추가 확인에 대한 답변

2026-10-02 · API 모듈 → 대시보드(웹 서비스) 팀

답변 감사합니다. 보내 주신 내용(카드 위치, 항목별 분해, 항목별 근거 키·관측 시각, 범위 산출, 약 10분 재계산, 이력 1차 제외, 신뢰 기준 밖일 때 값 숨김, 제외 사유 표시, 4주차 일정)은 모두 그대로 반영합니다.

**위험도 지수는 모듈이 계산해 결과 테이블에 넣습니다.** 합산값은 `farm_readings`의 축 `red_tide_risk` 한 행, 항목별 분해는 새 표 `risk_index_factors`, 상태는 `axis_status`의 같은 축에 둡니다. 지수는 계산값이라 `alertable`은 언제나 `false`입니다.

추가로 물어보신 네 가지에 답합니다. 아직 정해지지 않은 값은 "미정"으로 적었고, 정해지는 대로 결과 테이블 계약 초안(`tables-v3`)에 넣어 드리겠습니다.

---

## 1. 단계(레벨)는 누가 정하나요?

**모듈이 정해서 단계 코드로 넣습니다.** 말씀하신 대로 웹이 `value`를 잘라 단계를 만들면 판정을 다시 하는 것이 되므로, 단계도 모듈이 판정합니다.

- 통합계획서의 위험도 지수 설계에는 화면 예시(`●●●○○`)만 있고 **단계 경계값은 정해져 있지 않습니다.** 경계값·단계 수·코드 이름은 **미정**입니다
- 단계 코드는 지수 행의 `grade` 열에 넣지 않습니다. `grade`는 적조 공식 등급(예비특보·주의보·경보)에 쓰고 있어서, 섞이지 않게 따로 둡니다. 어느 열(또는 표)에 담을지는 계약 초안에서 알려 드리겠습니다
- 지수 범위(`lower`~`upper`)가 단계 경계에 걸치는지도 **모듈이 판정해 플래그로 넣습니다.** 웹은 플래그만 보고 "단계 경계 — 오차 안에서 달라질 수 있음"을 표시하시면 됩니다

## 2. 항목 이름·단위 목록

| `factor` | 입력값 | 단위 | 어디서 오는 값인가 | 항목 점수 |
| --- | --- | --- | --- | --- |
| `nearby_bulletin` | 양식장 해역의 최신 유효 적조 속보 등급 | 없음 (등급 코드 `NONE`·`PRE_ADVISORY`·`ADVISORY`·`WARNING`·`NOT_GRADED`·`UNKNOWN`) | 적조 축(`farm_readings` axis `red_tide`)과 같은 값 | 유효 속보가 있으면 등급에 따라 점수 — 등급별 점수는 **미정**. 유효 기간 안 속보가 없으면 0점 |
| `water_temp_band` | 추정 수온 | ℃ | 수온 축(`water_temp`)과 같은 값 | 24~27℃ → 1.0 · 22~24℃ 미만 → 0.5 · 그 밖 0 |
| `salinity_band` | 실측 염분 | psu | 염분 축(`salinity`)과 같은 값 — 4번 참고 | 32~33 → 0.5 · 그 밖 0 |
| `chlorophyll_level` | 최근 조사 클로로필a (표층) | ㎍/L | 클로로필 축(`chlorophyll`)과 같은 값 | 직전 조사보다 오르면 가산 — 비교 방식·기준·점수는 **미정** |

- 위 점수표·가중치(0.40·0.30·0.15·0.15)는 통합계획서 원안입니다. 원안 그대로 확정할지는 **미정**이고, 바뀌어도 열 구성은 같습니다
- 수온은 추정값이라 오차가 있습니다. 그래서 수온 항목 점수도 오차 범위를 반영해 범위로 내고, 지수 `lower`·`upper`에 반영합니다

**제외 사유 코드** — 항목을 계산에서 뺐을 때 분해 표에 넣는 값입니다. 화면 문구는 웹에서 붙여 주세요.

| 코드 | 뜻 |
| --- | --- |
| `SENSOR_QUALITY` | 관측값 이상으로 제외 (예: "클로로필 — 관측값 이상 제외") |
| `INPUT_NONE` | 입력 축이 신뢰 기준 밖(`provenance = NONE`) — 그 축의 사유를 함께 넣습니다 |
| `NO_INPUT` | 입력 값이 없음 |

"유효 속보 없음"은 제외가 아니라 정상적인 0점이라 사유 코드가 없습니다. 분해 표의 열 이름은 계약 초안에서 확정합니다.

## 3. 가중치·기여도의 의미

**기여도 = 가중치 × 항목 점수**입니다. 통합계획서 화면 예시의 `+0.40`·`+0.30`·`+0.08`(= 0.15 × 0.5 = 0.075)이 이 정의입니다.

- 네 항목이 모두 쓰이면 **기여도 합 = `value`** 입니다
- 항목 하나가 빠졌을 때(이상값 제외 등) 남은 항목만으로 다시 비율을 맞출지는 **미정**입니다. 이에 따라 "합 = `value`"가 항상 유지될지가 정해지므로, 합계 검산 표시 여부는 계약 초안을 보신 뒤에 정하시길 권합니다
- 저장 값은 반올림하지 않습니다. 화면에서 반올림하셔도 됩니다(0.075 → +0.08)

## 4. 염분 입력

**화면 염분과 같은 값을 씁니다.** 다만 한 가지 바로잡을 점이 있습니다.

- 모듈이 넣는 염분(`farm_readings` axis `salinity`)은 **계산값이 아니라 이미 양식장에서 가장 가까운 조위관측소의 실측값**입니다(`derivation = MEASURED`). 모듈에는 계산(추정) 염분이 없습니다
- 따라서 지금 웹에서 임시로 보이시는 "가까운 조위관측소 실측"은 모듈 염분과 같은 기준입니다. **모듈의 염분 축을 그대로 읽으시면** 화면 염분과 지수 근거 값이 같은 행이 되고, 분해 표의 `source_ref`로 같은 관측소인지 확인하실 수 있습니다
- 가장 가까운 관측소가 강 하구 영향을 받는 여수 관측소이면 염분은 `provenance = NONE`(신뢰 기준 밖)입니다. 이때 지수의 염분 항목도 `INPUT_NONE`으로 제외됩니다
- 통합계획서는 이 항목을 "정선관측 기준선"으로 적었지만, 위 기준을 쓰므로 지수의 염분 항목은 **실시간**(약 10분 갱신)입니다

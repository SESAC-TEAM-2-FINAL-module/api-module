# API 모듈 미정값 목록

작성 2026-09-27 · 기준: `API모듈_제작계획서_20260927.md`(개정 9) + skill 9종(`common-core`·`tide`·`bulletin`·`line`·`fishery`·`repository`·`interpolation`·`grading`·`evaluation`)

**이 문서의 쓰임**: 아직 정해지지 않은 값·규칙을 **누가 고르는가**로 나눠 한 곳에 모은다. 원천은 계획서다 — 여기서 값을 정해도 **계획서를 개정하고 같은 커밋에서 `CLAUDE.md`·skill을 갱신**해야 반영된다(계획서 A.8). 이 문서는 목록이지 결정 기록이 아니다.

**나눈 기준** (계획서 0.2절 "판정은 모듈, 표시는 대시보드")

- **A. API 모듈에서 선정** — 값을 고르면 모듈의 설정·코드·테이블이 바뀐다. 판정(영역·분류·자격)과 저장에 관한 것
- **B. 대시보드에서 선정** — 모듈의 결과 테이블을 **어떻게 보이고 언제 보낼지**. 대시보드 계약(계획서 5.5절)의 범위
- **C. 공동 결정** — 양쪽이 같은 값을 써야 하는 것

**읽는 법**: "막는 단계"는 그 값이 정해져야 "완료"되는 단계다(계획서 10절). "인계 전"은 S12 선행 조건이다.

## A. API 모듈에서 선정

### A1. 판정 정의 — `config/definitions.yaml`, 이미지에 포함, CI 게이트 ① 대상

값이 `<미결>`이다. 실행자는 값을 채우지 않고, 테스트는 설정에 상대적으로 짠다(계획서 12.1절).

| 키 | 무엇을 정하나 | 막는 단계 | 관련 skill | 참고 |
| --- | --- | --- | --- | --- |
| `line.surface_rule` | 표층 = 0m 레코드 채택 여부 | S9 | `line`(정의)·`grading`(적용) | 충족계획서 2절 결정 대기. 결정 전 DO는 `NONE`(`SURFACE_RULE_UNDECIDED`) |
| `grading.salinity_mode` | 양식장 염분의 영역 판정 — `NEAREST_TIDE` / `NONE` | S9 | `grading` | 값은 어느 쪽이든 저장. `dtRecent` 최근접 염분의 오차를 잰 산출물이 없다 |
| `grading.line_max_distance_km` | DO 정점 거리 한계 | S9 | `grading` | 가막만 합성 양식장의 최근접 정선 정점은 약 29km |
| `grading.fishery_max_distance_km` | 클로로필 정점 거리 한계 | S9 | `grading` | |
| `grading.excluded_zones` | 제외 구역(중심·반경 목록) — 섬진강하구 "인접"의 범위 | S9 | `grading` | 판단은 `grading`이 양식장 좌표로 |
| `bulletin.current_window_days` | 적조 현재값의 유효 기간 | S9 | `grading` | 적조 신선도(72h, 성공 호출 기준)와 다른 개념 |
| `interpolation.exclude_flatline` | 값 멈춤 관측소를 IDW에서 뺄지 | S8 | `interpolation` | |
| `interpolation.error_window_days` | 오늘의 오차 창 N일 | S8 | `interpolation` | **교차검증 결과를 보기 전에 고정**해야 한다 |

**기본값으로 구현하되 결정 대기인 것** — 값이 있어 게이트는 돌지만, 팀 결정이 나면 바뀔 수 있다

| 키 | 현재 기본값 | 결정 사항 |
| --- | --- | --- |
| `line.cast_gap_minutes` | 60 | 캐스트 키 X (10~720분 어디서나 결과 동일) |
| `interpolation.method` · `n_neighbors` | `M2` · 5 | `B2` N=2 승격 여부 |
| `interpolation.align_window_min` | 30 | IDW 관측값 정렬 창 |

### A2. 운영 조정 — ConfigMap, 인계 후 인프라 소유, **인계 전 전부 결정 필요**

스키마가 `<미결>` 자리 표시를 거부하므로, 정해지지 않으면 ConfigMap으로 기동할 수 없다(계획서 2.0.6절). 인계 뒤에는 인프라가 값을 바꾸고, 초기값은 팀이 정한다.

| 키 | 무엇을 정하나 | 관련 skill | 참고 |
| --- | --- | --- | --- |
| `tide.flatline_minutes` | 값 멈춤 감지의 N분 | `tide` | 운영 조정 중 `processor`가 쓰는 유일한 키 — 판정 재생으로 확인되지 않고 스키마·PR 리뷰로만 지켜진다 |
| `stale_threshold_hours.salinity_tide` | `dtRecent` 염분 신선도 | `evaluation` | 518분 연속 결측을 정상으로 볼지와 함께 |
| `stale_threshold_hours.tide_level` · `wind_speed` · `air_temp` | 물때·풍속·기온 신선도 | `evaluation` | v1.5에 키 없음 |
| `stale_threshold_hours.dissolved_oxygen` | DO 신선도 | `evaluation` | v1.5 값 2160(90일)을 가져오면 데모 내내 STALE 가능. **I-4의 0m DO 집계 결과를 보고** 정한다 |
| `evaluation.interpolation_stale_minutes` | 수온 추정 지연 한계 | `evaluation` | 관측 임계(3h)를 그대로 쓸지 포함 |
| `evaluation.grading_stale_minutes` | 산출 지연 한계 | `evaluation` | |

이미 값이 있는 운영 조정: `stale_threshold_hours.water_temp: 3`, `red_tide_bulletin: 72`. 적조 시즌은 개정 9로 운영 조정에서 빠져 **시드**(A3)로 옮겼다.

### A3. 구조·규칙 — 계획서에 규칙이 없다

계획서에 규칙이나 값이 없는 것이다. 실행자는 만나면 멈추고 보고한다. `axis_status.state` 값 목록·상태 겹침 우선순위·계절 밖 판정의 원천은 **개정 9로 해소**됐다(계획서 4.9절).

| 항목 | 무엇이 비었나 | 관련 skill | 영향 |
| --- | --- | --- | --- |
| **0m 레코드가 둘 이상인 캐스트** | 처리 규칙 없음. 실측 0건(324캐스트 모두 1개) | `line`·`grading` | 낮음 — 만날 가능성이 작다 |
| **적조 해역 시드 내용** | `area_aliases`(초기 별칭), `areas`(해역 목록·중심·반경), `axis_coverage`(해역 × 축 선언 — **적조 계절 포함**, 계절 밖 판정의 유일한 원천)의 작성 주체와 출처 | `bulletin` | **인계 전.** 실데이터의 적조 양식장 대응과 계절 밖 판정이 막힌다. 근거: 별칭은 재검증 A의 `txt_seas` 원문(있음), 해역 중심·반경은 출처 필요(v1.5 "14.2절 실험 산출물" — 받은 자료에 없음), 계절은 팀 판단 |
| **R1 하구 예외 정점 목록** | 염분 < 31.0 psu 규칙에서 뺄 하구 정점 | `common-core` | 섬진강하구 정점이 생물부착 의심으로 잘못 걸릴 수 있다 |
| **R4 태풍 특보 입력 원천** | 급변 규칙의 태풍 면제에 쓸 특보 정보를 어디서 받는지 | `common-core` | 태풍 중 급변이 품질 불량으로 걸릴 수 있다 |
| `farm_reading_history` 보존 기간 | 곡선용 시계열을 얼마나 둘지 | `repository` | DB 소유 측과 협의 |
| 적조 위험도 지수(v1.5 7.4절)의 범위 | 이 모듈이 만들지 여부 | — | 결정 전까지 설계·구현하지 않는다 |

## B. 대시보드에서 선정 — 대시보드 계약(계획서 5.5절)

모듈은 판정과 값을 적재하고, 아래는 대시보드가 고른다. **모듈의 판정을 다시 계산하지 않는다**는 것이 전제다.

| # | 항목 | 모듈이 주는 것 | 대시보드가 고를 것 | 근거 |
| --- | --- | --- | --- | --- |
| B1 | **"확인 불가" 한계** | `axis_status.last_checked_utc` | 이 시각이 얼마나 지나면 "확인 불가"로 보일지(한계값)와 문구. 모듈이 멈췄을 때 이것이 유일한 신호다 | W3 |
| B2 | **발송 시점 규칙** | `alertable`(정적 자격), `axis_status.state`, 이력 | 등급 상승 시에만 보낼지, 새 속보만 보낼지, 구독·중복 억제 규칙. 발송 후보는 **`alertable = true`이고 `axis_status`가 정상인 축**으로 이미 정해져 있다 | W5 |
| B3 | 알림 문구 | `grade`, `derivation` | `UNKNOWN`의 "속보 발생", 인근 실측 값임을 낮춰 표기하는 방식(v1.5 "등급 하향 후 발송") | W5 |
| B4 | **해역 미상 속보 표시** | `bulletins`(대응 양식장 없음) | 보일지·어디에 보일지. 팀 논의 권고: 전 양식장에 "해역 미상 속보"로 표시, 발송하지 않음 | W6 |
| B5 | **분류별 화면 문구** | `axis_status.state`·`reason` | 상태 17종(계획서 4.9절 상태 값 표)마다의 문구. v1.5 4.5절 "화면" 열이 기준 | W8 |
| B6 | 비대상 종 속보 표시 | `bulletin_details.grade = NOT_GRADED` | 보일지·어떻게 보일지. 모듈은 자체 등급을 만들지 않는다 | v1.5 20절 |
| B7 | "발송 안 된 것" 패널의 "유의한 변화" | `farm_reading_history`, `alertable` | 무엇을 유의한 변화로 볼지 — API 지식이 아니라 제품 정책이다 | W7 |
| B8 | 클로로필 조사 기준 추정의 **표시** 여부 | (계산은 A1이 아니라 판정 정의 스위치 `grading.chlorophyll_estimate_enabled`, 기본 꺼짐) | 계산이 켜졌을 때 보일지 | 11절 |

**선정이 아니라 지켜야 할 요구사항** — 고를 여지가 없고 구현만 하면 된다

- **W1** 배지는 `derivation`과 축으로 정한다. 계산값에 `인근 실측`·`공식 발표` 배지를 붙이지 않는다
- **W2** `provenance = NONE` 값은 표시하지 않는다(값은 근거 보기·운영 확인용으로 남아 있다)
- **W4** `farm_readings`와 `axis_status`의 순간 불일치는 `basis_utc`와 `computed_at_utc`로 감안한다

## C. 공동 결정 — 양쪽이 같은 값을 써야 한다

| 항목 | 현재 | 왜 공동인가 |
| --- | --- | --- |
| **축 키 이름** | *(제안)* `water_temp`·`salinity`·`tide_level`·`wind_speed`·`air_temp`·`red_tide`·`dissolved_oxygen`·`chlorophyll` | 모듈은 이 이름으로 쓰고, 대시보드는 이 이름으로 읽는다 |
| `axis_status.state` 값 목록 | **확정(개정 9)** — 17종, 계획서 4.9절 | 모듈이 판정하고 대시보드가 문구를 붙인다(B5). 값을 바꾸려면 양쪽이 함께 계획서를 개정한다 |
| 계약(`contracts/`) 배포 방식 — 버전 태그 / 패키지 | 버전 태그 기준으로 작성 | 대시보드가 계약을 받는 방법 |

## 채택 순서 제안

앞 단계의 결과가 뒤 단계의 근거가 되도록 줄 세웠다. 같은 번호 안은 동시에 정해도 된다.

| 순서 | 무엇을 | 왜 이 순서인가 | 막는 것 |
| --- | --- | --- | --- |
| **1** | C의 **축 키 이름**, A4의 **결과 코드 → 분류** *(제안)* | 모듈과 대시보드가 같은 이름을 쓰는 바탕이다. 나머지 모든 결정이 이 이름으로 적힌다 | 전 단계 · 대시보드 |
| **2** | A1의 **`line.surface_rule`**(충족계획서 2절 결정) | 이미 근거가 있다(324캐스트 모두 0m 정확히 1개). DO 관련 결정의 전제다 | S9 |
